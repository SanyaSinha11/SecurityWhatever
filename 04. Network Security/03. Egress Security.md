# Overview
Egress means data or network traffic leaving an organization's environment.

Egress security is the set of controls used to monitor, restrict, and protect outbound network traffic and data leaving an organization's systems.

The primary goal is to prevent things such as:
- Sensitive data being uploaded to unauthorized websites
- Malware communicating with an attacker
- Employees accidentally sending confidential information outside
- Attackers stealing data after compromising a machine
- Secrets/API keys being transmitted externally
- Unauthorized cloud storage uploads

## Why is Egress Security important?
Traditional security often focuses heavily on **incoming threats**.
But even if an attacker gets inside, the organization still needs to prevent them from taking data out.

Modern security therefore looks at **both directions**.

A compromised endpoint may be communicating with:
- Command-and-control (C2) servers
- Malicious domains
- Cloud storage
- Attacker infrastructure
- Anonymous file-sharing services
This makes egress monitoring particularly important for **incident detection and response**.

# Data Exfiltration
Data exfiltration is the unauthorized transfer of data from an organization's environment to an external destination.

In simple terms:
**Data theft = data exfiltration.**

The movement of data outside the organization is exfiltration.
The security team might detect:
- Large outbound transfer
- Unusual destination
- Unusual user behavior
- Sensitive file classification
- Abnormal process activity
- Connection to a suspicious domain
### Ways it can Happen
Common channels include:
1. Web uploads
   uploading confidential documents to an unknown file-sharing service.
2. Cloud Storage
   storing company data on personal cloud storage (might be against company policy)
3. Email
   sharing companies data through attachment to external emails
4. USB/Removable media
   an employee could copy sensitive files to removable storage
5. Malware communication
   malware can establish communication with an attacker's infrastructure, the attacker may then instruct the malware to collect and transmit data
6. DNS exfiltration

# Data Loss Prevention (DLP)
DLP is a security control designed to identify, monitor, and prevent sensitive data from being improperly accessed, transmitted, or shared.

DLP doesn't necessarily know that something is sensitive simply because of the filename.
It can use different techniques.
1. Keyword matching - 'confidential', 'internal use only', 'customer data', etc.
2. Regular expressions - like detecting patterns associated with credit card numbers, phone numbers, government id, etc.
3. Data classification - org may classify their data as public, internal, confidential, restricted, etc and DLP policies can be applied based on such classification
4. Fingerprinting - DLP can recognize known sensitive documents or data patterns
5. Context - modern DLP can consider who is sending data, what data is being sent, etc

#### DLP example in SOC
Suppose:
An employee downloads a confidential customer database and attempts to upload it to an external website.

The security flow would be like:
```
	Employee
	   ↓
	Downloads sensitive file
	   ↓
	Attempts external upload
	   ↓
	DLP inspects content
	   ↓
	Sensitive information detected
	   ↓
	Policy violation
	   ↓
	Upload blocked
	   ↓
	SOC alert generated
	   ↓
	Incident investigated
```
This is where **DLP + incident response** become connected.

# Data Security Posture Management (DSPM)
DSPM focuses on discovering, classifying, monitoring, and protecting sensitive data across an organization's data environment.

Most Important term is - ***Data Visibility*** 

DSPM tries to answer:
*Where is our sensitive data, who can access it, how is it being used, and is it properly protected?*

DSPM identifies:
- Sensitive data
- Location
- Ownership
- Access permissions
- Exposure
- Misconfigurations
- Data movement
- Risk

DLP is primarily focused on preventing sensitive data from being improperly transmitted or shared, whereas DSPM provides visibility into where sensitive data exists, who can access it, how it's being used, and whether it's exposed or inadequately protected.

---
# Cloud Security Posture Management (CSPM)
CSPM is used to identify and remediate security misconfigurations and compliance risks in cloud environments.

For example:
AWS S3 Bucket
      ↓
Publicly accessible
      ↓
Sensitive customer data

CSPM can detect:
*"This storage bucket is publicly accessible."*
That's a **cloud configuration problem**.
